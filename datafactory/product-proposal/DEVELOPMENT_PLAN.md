# DataFactory 产品开发计划

计划基线 v1.0 · 2026 年 11 月 17 日

需求来自[产品设计](PRODUCT_DESIGN.md)，交互以[26 页原型](prototype/index.html)为参照，设计与契约遵循[技术架构](TECHNICAL_ARCHITECTURE.md)。当前 `arch_dev` 上可评审产品文档与原型。下文的服务、作业和验收场景是开发目标。

## 1. 目标与组织

交付顺序为独立平台基座、两账户 RAGFlow 授权与复用、Embedding/Reranker 生产、LLM SFT/偏好生产、评测与企业验收。每个阶段形成可独立演示的纵向流程，后续任务依赖已通过的契约。

| 工作面 | 应交付的代码和验收 | 对接人建议 |
| --- | --- | --- |
| RAGFlow 集成 | 资源委托、短期授权、知识库捕获、检索、模型调用与契约探针 | RAGFlow 服务负责人 |
| DataFactory 后端 | 项目身份、连接仓储、元数据、作业、API/事件、交付与审计 | 后端负责人 |
| 核心引擎 | 领域 Schema、节点、执行 plan、采样、分组、审核规则、质量和适配器 | 引擎负责人 |
| 前端 | 26 页交互、响应式工作台、接入/模型授权、新增状态与错误反馈 | 前端负责人 |
| 验收 | 双账号隔离、多阶段运行故障、目标训练器读回、逐页交互可用性 | QA、建模和数据质量负责人 |

以 1 名后端、1 名核心引擎、1 名前端，加 RAGFlow 接入与 QA 分时协作为估算基准。关键路径约 13 周，阶段 0 验证上游能力后重估。团队可以在确定的 OpenAPI 和引擎端口上并行开发，具体周次是规划估算。

## 2. 阶段与退出条件

| 阶段 | 估计时间 | 核心实现与交付 | 必须通过的退出条件 |
| --- | --- | --- | --- |
| 0 · 契约与可行性 | 第 1 周 | 确认目标 RAGFlow 实例运行时、代码/镜像版本、数据与模型权限。用隔离实例验证切片全量读取、资产引用、索引/源修订、用量。确定两接口的 Schema、批准与撤回时序、语料与模型端口。设计环境信任根、低预算测试账号和独立存储 | 记录目标测试实例、能力与限制。有稳定捕获和权限方案，明确临时授权、用量缺失与未知计费的终态。缺必要能力的操作在契约标记为不可用 |
| 1 · 平台与文件闭环 | 第 2–3 周 | 独立 uv workspace、前端工程、数据库迁移、OIDC、项目 RBAC、作业租约、SSE、对象存储。引擎 Schema 与夹具。CSV/JSONL、S3 预检与冻结，非模型的样例进入数据集、人工审核和 canonical 导出 | 不配置 RAGFlow 可启动并完成文件小批链路。平台和上游会话分离。坏行、越权、部分失败、重复提交有诊断。26 页路由、布局和数据状态按分期接通 |
| 2 · RAGFlow 连接与模型复用 | 第 4–6 周 | 集成端登记项目服务身份、批准页、项目范围授权与令牌。后端来源/模型连接、撤回与状态同步、快照捕获及资产读取。复用词面/混合检索和 Embedding/Reranker/LLM 基础调用，完成调用 ID、预算预留、实际结算、查询与核账 | 同一项目接入 A/B 两个私有库并冻结；读/召回按授权分开。模型独立授权，已发令牌在撤销后失效。交叉库/账号/项目/证书复用均被拒绝。真实持久化和替身计费测试通过 |
| 3 · 检索与重排生产 | 第 7–8 周 | Embedding 和 Reranker 模板、可复用步骤配置、小批预览、审阅量表、难负例、候选组，候选数据集和分组质检，发布审签。交付检索标签、Embedding JSONL、Reranker 分组和目标训练器适配器 | 预览和生产执行计划等同。假负例可改判，未判定与 0 分分离，跨集合冲突阻断冻结。两个模型训练输入在固定版本加载器读回。快照、运行、审核、发布血缘可核对 |
| 4 · LLM 制作 | 第 9–11 周 | SFT 多轮消息、证据、训练轮与工具验证，偏好盲审、平局/无效、双标与仲裁，模板和角色、TRL 等样例适配器。模型出域和授权联动 | 证据越权、无效调用参数和不一致偏好上下文均阻断。平局不进训练对。A/B 匿名及模型版本可审计，SFT/DPO 交付格式读回 |
| 5 · 评测、运营与开发验收 | 第 12–13 周 | 锁定评测集、基线/候选比较和回归样本，审计与使用限制、评测回流、规模测试。按优先级接入日志增量及更多媒体适配。部署 91 的独立开发环境，补齐正式使用与运维步骤 | 26 页均具备可用数据状态，主流程 Chrome 测试通过。授权撤回、续跑、审批竞争、评测锁定、下载哈希和备份恢复验证通过。报告注明目标连接实例和覆盖的训练器版本 |

阶段 1 的文件流程与阶段 2 的上游连接复用统一领域契约。阶段 2 的授权、捕获和模型账目是依赖 RAGFlow 的生产运行进入后续阶段的门槛。初期实时检索按授权库分开。上游能力不足时显示确切原因，可以交付依靠导入候选和人工标注的任务。

## 3. 实施分解

### 契约、数据和连接

1. 定义 `SourceRef`、`SnapshotManifest`、`Segment`、`ModelRef`、`Invocation`、`Sample`、`QualityReport` 的 Schema 与最小夹具。两套 OpenAPI 分别描述 DataFactory Web API 和 RAGFlow 集成端。生成前端类型并在 CI 比对差异。
2. 落库独立身份、项目成员、来源权限、模型权限、分集和发布对象。建立状态机、事件序号、分页游标、幂等约束与数据库迁移测试。持久化连接的上游实例与授权范围。
3. 接入结构化语料与 S3 前缀授权，预览列与行错误，按稳定版本和媒体 hash 导入。RAGFlow 侧验证资料已处理，按可验证的读取版本捕获。源变更、缺页、超出处理上限、资产缺失分别提供诊断。
4. 构建上游批准页与项目服务身份验证。在批准、列目录、冻结、检索、模型调用及下载的入口分别检查授权。两账户测试先使用不同角色与私有库，再覆盖不同实例重复 ID、不同向量空间和同名模型。
5. 模型端建立模型能力目录、一次调用的状态和账目。首次连接先用无成本验证和预估，真实抽样用到已批准额度。淘汰按模型名或请求用户字段决定上游身份的路径。

### 引擎、质量和交付

1. 建立版本化配方及编译器，解析依赖、权限、模型能力、输入范围和资源上限。预览通过同一执行器运行较少分层样本。
2. 固定分组和集合后运行召回、采样、生成和评分。保存候选池和原始分数。每批提交绑定序号、运行版本、每源权利和存储哈希，重放使用原输入和已确认产物。
3. 依次接通四个任务视图。使用可核验的正负例、分级相关性、结构化消息和已裁决偏好，由统一事实层生成。人工改判加入审核版本并重新验证影响。
4. 实现强制门禁与可审批告警。冻结选择的有效记录和适配器版本。导出使用固定顺序、校验文件和目标加载器读回，处理样本计数、跨集合和媒体完整性。
5. 评测绑定固定测试、候选快照、模型、协议和评分版本。训练数据回流只使用经批准的新记录或归纳出的失败模式。

### 前端按原型交付

| 原型编号 | 页面 | 正式实现的增量 |
| --- | --- | --- |
| 01、02、26 | 登录、项目总览、项目设置 | OIDC、项目和角色、真实待办、成员与预算、审计及会话回跳 |
| 03–08、25 | 数据源、接入、来源详情、语料快照、快照详情、语料检视、模型连接 | 由原型连接表单扩充成项目授权向导。分组查看不同实例与账户，补齐待审批、已批准、过期、撤回、处理失败和可安全诊断 |
| 09–13 | 配方库、模板库、配方设计器、运行记录、运行详情 | 类型化步骤配置、校验/预估、小批预览、冻结输入、SSE、批次和开销 |
| 14–18 | 数据集、数据集详情、样本详情、标注审核、审核工作台 | 四种任务视图，证据定位、候选等级和工具核对、偏好盲审、并发判定与修订 |
| 19–23 | 质量中心、划分、发布与导出、预检与冻结、导出预览 | 规则版本、可跳到错误记录的阻断、变更后重检、权限与审批、加载器验证、下载 |
| 24 | 基准评测 | 锁定测试、同一协议比较、评测记录与回流 |

原型的共享导航、卡片、双栏检视、表单与窄屏审核卡片是视觉对照。阶段实施时逐页核对信息密度、操作可达性及重要状态。页面数据由生成客户端和 API 驱动。新功能先补齐设计、入口、可用状态和验收，再纳入对应一页或现有页内视图。

## 4. 验证矩阵

| 编号 | 验证链路 | 预期结果与证据 |
| --- | --- | --- |
| T01 · 独立工作 | 文件导入、快照、预览、审核、导出。停止 RAGFlow 测试服务 | 文件与人工流程正常，后台本方任务可复查。分别记录未连接来源、上游中断与本系统 API 故障 |
| T02 · 双账户 | 同一上游的 A/B 两个私有库分别批准给同项目。第三库 C 未批准 | A/B 均列出并进入同次快照及样本，血缘区分。伪造账户、库、文档、游标或资产 ID 无法访问 C |
| T03 · 凭据隔离 | 其他项目、实例或证书使用 A 的短期令牌。审批链接重放、待审批尚未批准 | 访问失败，待批申请无资源权限。轮换证书后以相同登记身份申请新令牌可恢复 |
| T04 · 撤权与并发 | A 在扫描、生成、预检和下载期间分别撤权，B 保持有效 | 旧令牌失效，无新批次或新下载。混合产物受限，B 独立连接继续有效。记录发现、暂停和审计时差 |
| T05 · 一致性和媒体 | 超过 1024 个片段、重复标题、取数中重切、截断分页、未授权同名图片 | 全量、稳定读取后才冻结；异常不提交 READY；资产必须引用授权片段 |
| T06 · 模型及检索 | A/B 不同模型/维度、同名异实例、授权模型撤回、B 限制外发 | 按库召回并保留各自版本与排名。不允许跨授权合并向量，禁止未获准出域，实例/能力改变提示重选 |
| T07 · 运行与预算 | 2 Worker 同时领取、重复请求、失效代次提交、模型接收后超时、定额耗尽 | 单次逻辑提交和单次有效预留。待核账保留额度并查询同一调用；恢复复用已提交分片 |
| T08 · 四类训练与门禁 | 真/假负例、未判定等级、工具引用错误、假偏好对、评测污染、发布审批后改判 | 错误准确定位并阻断，修正后重新预检。下载包通过目标版本加载器，标签和训练字段数量可核对 |
| T09 · UI | 从总览、源向导、证据链接、审核台到发布预检，测试正常/加载/空/拒绝/恢复及窄屏 | 逐页对照原型与产品要求，检查键盘与对比度。测试用例执行真实浏览器流程并记录通过集 |
| T10 · 部署恢复 | 独立环境安装、仓储/对象恢复、API 回退、Worker 重启 | API 健康、作业领取恢复、无孤立发布和跨环境写入。记录备份与实测恢复时间 |

本地单测以内存端口、合成数据与固定随机种子运行。连接契约使用可复现的 HTTP 夹具和项目证书，额外在隔离 RAGFlow 复核同一契约。持久化测试使用真实隔离 PostgreSQL 和对象存储覆盖事务及恢复。浏览器 E2E 覆盖主流程与拒绝场景。真实模型测试走独立预算、单次小样和核账路径。

## 5. 发布门槛与持续维护

- 每个阶段评审按需求、Schema/API、主要正常流、权限/失败流和测试结果提交记录。开发指南和产品设计只记录有效路径和已验证的边界。涉及已有 RAGFlow 接口时先核对对应实现和上游契约版本。
- 阶段 0 签收稳定读取、模型用量和 PKI 运维依赖。可运行后，91 部署前验明数据库、对象桶、队列和 RAGFlow 权限/计量均隔离。开发验证在本地或 91 完成。
- 上线准备检查包括协议版本与返回的能力、库/模型批准成功率、限流与失败恢复、关键角色权限和运行续跑。验收报告写明测试版本、快照片段数、样本类型、负例和限制项。交付包报告用样例 hash 及加载器验证结果证明可消费性。
- 代码形成后补充启动、诊断、权限失效、备份、恢复与回退的可执行步骤到 [operations.md](../../files/operations.md)。整体变更写入 [update.md](../../files/update.md)，现场问题记录到 [issue.md](../../files/issue.md)。

各目录的实现和检查要求见 [DataFactory 总则](../CLAUDE.md)、[核心引擎](../engine/CLAUDE.md)、[后端](../backend/CLAUDE.md)和[前端](../web/CLAUDE.md)。

3.4 源码构建依赖与 ChromeDriver 缺失排查

2026-10-30 在 91 复现构建报错 failed to calculate checksum ... /chromedriver-linux64-121-0-6167-85: not found。这个路径属于 Dockerfile 的外部依赖镜像，不是宿主机构建上下文。实查上游 infiniflow/ragflow_deps:latest 已切换为 Go 依赖内容，除 ChromeDriver 外还缺少 Chrome、Tika、uv 等 Python 构建资源。

6.2 全存储冷备

# 等待当前任务结束，两端应用主机分别执行
bash docker/docker.sh stop app
# 92：列出全部应用 API 地址
APP_STOPPED=1 APP_URLS="http://192.168.88.91:9380 http://192.168.88.92:9380" \

脚本检查端点不响应、七个卷确属 ragflow-storage 后停止存储，只读归档 mysql_data、es_data、es_snapshots、minio_data、redis_data、kibana_data、redisinsight_data；校验 gzip 并生成 SHA256SUMS。结束后只恢复原先运行的存储容器，不自动启动应用。检查状态健康后再分别启动两端应用。

APP_STOPPED=1 是操作者确认。网络不可达不能证明远端 Worker 已停，应检查每台主机的容器实际状态。同一备份集合还须保存两端 app.env、storage.env、源码版本与差异和镜像记录，权限 600。

6.3 恢复顺序

  1. 在独立位置校验 SHA256SUMS 和压缩包，先恢复到独立测试卷，不能覆盖在用数据。
  2. 使用备份对应版本的存储镜像。冷备数据解包到各自空卷；在线 SQL 导入独立 MySQL 实例。物理数据库目录不能直接跨大版本复制。
  3. 数据、env 密钥和代码作为一组切换。只恢复 MySQL 会造成 ES 向量、MinIO 对象、Redis 任务不一致。
  4. 停止全部应用写入，验证恢复存储健康和业务对象关联后再切换连接配置，重建应用。
  5. 使用独立探针和真实只读查询验收。保留旧卷以便回退，不运行全局清理。

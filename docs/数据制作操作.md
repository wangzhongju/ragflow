更新：2026-11-04。开发入口：[RAGFlow 数据制作](http://192.168.88.91:8088/data-factory)。使用已有 RAGFlow 登录身份；页面不要求另填 API Key。生产环境尚未部署数据制作模块。

## 1. 准备来源

1. 在知识库中建立专用测试库，选择用户已配置的 Embedding 模型。知识库的向量维度与检索编码模型必须一致。
2. 选择解析管道，上传文件，等文档状态为 DONE。制作模块读取已启用 Chunk，不重新执行 OCR 或文档解析。
3. 人工核对原件、正文、表格、公式、图片说明与页码。公式 OCR、双栏阅读顺序、表格数字和 ASR 转写错误必须先修正。完成状态不等于内容正确。
4. 音视频先经原有 ASR/VLM 管道形成可检索内容，制作时同时固化媒体原件。截图、图片裁剪与提取文本保留原件关联。
5. 如果知识库没有已有 questions，创建实例时选择“模板”或“LLM 生成”。模板仅是审核起点，不能直接视作真实用户问法。

## 2. 创建实例

点击顶栏“数据制作”→“创建实例”，选择 Embedding、Reranker 或 LLM。配置在实例创建后固定；更改生成参数时创建新实例，保留对照与可复现记录。

- **问题来源**：复用已有问题；已有问题加模板补充；LLM 生成。选择生成模型、提示词、每块问题数、最多样本数、输出长度、调用次数和 Token 预算。
- **候选检索**：关键词/BM25、向量、混合；当前文档或实例来源范围；混合权重、相似度阈值、候选数量、Top K、候选池；可选 Rerank 模型。无需跳转知识库修改这些任务参数。
- **样本规则**：正负例数量、困难负例比例、近重复阈值、负例相关性上限与模态。Rerank 分数并非统一概率，需要按所选模型校准阈值。
- **分区**：按文档家族与重复内容分组，保存训练/验证/测试分区，同一租户跨实例保留分区约束。少量文档可能全部落入同一分区，不强行随机分样本凑比例。

低费用起步建议：模板、关键词检索、不启用 Rerank、最多 5 条样本、外部调用 0 次。需要验证模型时，单独开一个 1 条样本实例，最多 3 次调用、输出 256 Token，并给足输入预留预算。LLM 生成器除问题生成外还要生成回答。

预算是调用前按输入字节数及输出上限保守预留的工作量指标，不是云账单精确 Token 数。检索编码和 Rerank 分开记账；上游知识库解析、模型 SDK 内部重试不在制作作业预算内。失败或取消后不自动重复不确定的模型调用；重新提交前先核对记录。

## 3. 人工标注与质量检查

### Embedding

1. 阅读问题和正例，确认能回答问题。将模板问题改成真实问法。
2. 展开每个候选负例，检查它是否也能回答问题、是否包含正例正文、是否只是同页图片或不同文档的复制段落。
3. 疑似相关的负例点击“改为正例”；无意义候选点击“移除此负例”。困难负例不足应补充同领域、内容相近但不回答问题的来源，不以随机负例冒充困难负例。
4. “浏览同分区证据”可查看更多 Chunk。高级 Payload 中可增加多个 positives 或 negatives，负例须记录 evidence_id 和 method（人工添加用 manual）。
5. 图文配对可将 query 写成文本加 image 的 ContentPart；纯图片问题也允许。图片、音频、视频只能引用当前实例资产 ID，不填写临时 URL 或 Base64。
6. 审核备注说明纠正依据，再批准。结构检查会阻止正负重复、内容包含冲突、跨分区和越权资产引用，但语义相关性仍由审核者负责。

真实回归案例：图 1 的正文与附带相同正文的图片 Chunk 曾分别成为正例和负例，Rerank 分数约 0.996。修正后包含关系检测阻止发布，高相关候选从自动负例池隔离。原演练实例保留供核对，不作为训练数据发布。

### Reranker

对每个候选标注：0 不相关、1 部分相关、2 高度相关。来源正例初始为 2，挖掘候选为“未标注”，必须完成等级审核；至少两个候选且有等级差才可发布。不要把所有非来源候选机械标为 0。

### LLM

核对问题、回答和引用证据；删除无依据结论，必要时表达证据不足。高级 Payload 支持多轮 messages 和 supervised_turns，后者只允许指向 assistant 轮次。图片/音视频语义生成目前复用知识库已生成的文本表示；需要视觉或声音细节的训练样本，必须人工检查媒体并把相应 ContentPart 放入对话。

“质量检查”检查结构、证据、分区、冲突、重复与疑似密钥。它不计算训练后 Recall、MRR、NDCG、跨模态召回或编码性能，也不替代完整敏感信息审查。

## 4. 冻结和导出

1. 完成审核后点击“冻结已批准样本”。草稿与驳回样本不进入版本。
2. 选择版本及适配器，下载 ZIP。已冻结版本绑定具体样本修订；后续修改不改变已有发布包。
3. 校验 manifest.json 中的文件 SHA-256。train/validation/test.jsonl 保存固定分区；assets/ 使用相对路径；provenance.jsonl 保留挖掘与审核来源。
4. 原件、页面图、提取文本等通过资产清单保留派生关系。同一租户同一内容只存一份对象，不把图片音视频写进 MySQL/SQLite 或 Elasticsearch。
5. 不支持某种模态的适配器会拒绝导出，不会静默丢弃图片、音视频或结构化内容。

| 适配器 | 用途 |
| --- | --- |
| canonical-v2 | 三类任务完整多模态标准 |
| sentence-transformers-triplet-v1 | 文本 Embedding anchor/positive/negative |
| reranker-pointwise-v1 | 文本 query/document/label |
| messages-v1 | 多模态消息及证据，供外部转换器使用 |
| llama-factory-sharegpt-v1 | ShareGPT 对话、媒体相对路径、dataset_info.json |

LLaMA-Factory 适配器要求 user/assistant 交替、监督所有 assistant 轮次；区域或时间片段应先物化为独立媒体文件。模型是否支持音视频、模板与训练超参数由外部训练工程决定。仅有数据集不能直接完成训练，还需要基础模型、训练代码/框架和配置。本模块不启动训练或训练后评测。

## 5. 部署、恢复与停用

制作服务：`data_factory/compose.yaml`，独立 SQLite 元数据卷、MinIO 资产桶、单 Worker，1 CPU/2 GiB。源代码挂载只读，宿主端口仅 127.0.0.1:9392。

私有 `data_factory/.env` 配置 RAGFLOW_IMAGE、RAGFLOW_API、RAGFLOW_NETWORK、FACTORY_MINIO_ENDPOINT、FACTORY_MINIO_ACCESS_KEY、FACTORY_MINIO_SECRET_KEY、FACTORY_MINIO_BUCKET。91 使用独立桶 ragflow-data-factory。凭据不写入本文件或 Git。

RAGFlow 私有 `docker/env/app.env` 配置：

```dotenv
DATA_FACTORY_URL=http://ragflow-data-factory-workbench-1:9392
RAGFLOW_QUEUE_NAME=te.dev91
```

API 与 Worker 必须使用同一个 RAGFLOW_QUEUE_NAME。91 的两级队列为 te.dev91.0.common、te.dev91.1.common；92 保持 te.0.common、te.1.common。默认 dev 为 te.dev，显式配置 dev 使用 te 会拒绝启动。Redis、MySQL、ES、MinIO 仍共享，这次隔离的是解析任务队列，不是完整数据环境。

```bash
cd /home/cdky/workspace/github/ragflow/data_factory
docker compose up -d --pull never
docker compose stop workbench
docker compose start workbench
```

队列配置更改需重建 91 app 使 API 和 Worker 同时生效；只修改交互 shell 的环境变量无效。重建前检查旧任务，取消/完成本环境任务后重新提交，勿清空共享生产队列。

停用制作服务后，网关 capabilities 返回 enabled=false，主应用知识库与聊天仍可用。恢复后生成中任务标为 interrupted，需要重新授权继续。单 Worker 的取消代次与调用账本避免旧结果覆盖或费用失控。

迁移前已用 SQLite backup 保存 factory.pre-v2-nov04.sqlite3。旧发布 ZIP 按原始字节保留；迁移后的新实例使用 Canonical v2。回退须同时匹配代码、数据库和对象存储，不能只回退数据库。删除实例只回收不再被其他实例或发布版本引用的对象。

前端独立部署可以复用同一 React 构建和 API 网关，当前只交付 RAGFlow 内嵌入口，不维护第二套页面。后端模块与 RAGFlow 业务表无反向依赖。

## 8. 管道编辑数据与执行数据的区别

通过 API 克隆或生成管道时，保留模板的 graph.nodes[].data.form，再按表单格式修改；不要把 components[].obj.params 整体复制到 form。Parser 表单 setups 是含 fileFormat 的数组，执行参数则是格式映射；TokenChunker 表单 delimiters 是 {value} 数组、image_table_context_window 是统一上下文窗口、overlapped_percent 使用百分数，保存时由前端转换为执行参数。

本次验收管道已修正该错误。创建后应从 Web 打开 Parser/Chunker，保存并刷新，同时核对执行参数，不能只以解析任务成功判定画布可编辑。详见[问题记录](issue.html#data-factory-pipeline-ui)。

出现 `.map is not a function` 时，先根据浏览器堆栈定位具体组件，再备份并检查该管道 DSL；同样报错不一定是同样原因。本次修复只修改共享数据库内指定管道的画布表单和 91 私有 `create-pipeline.py`，未修改前后端业务源码。详细修改清单、正常结构示例、接口保存注意事项、现场证据路径及回退方法集中在 [issue.html 的管道 Web 修复章节](issue.html#data-factory-pipeline-ui)。现场脚本绑定本次管道和备份，不应直接用于其他实例或反复执行。
